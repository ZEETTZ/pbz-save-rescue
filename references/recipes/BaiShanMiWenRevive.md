# 白山秘闻·复活剑偶（BaiShanMiWenRevive）

## 适用场景

玩家把「廿一号·剑偶：玉璧」提前击杀了，导致白山密闻失败（`QC_Failed`，任务里残留
`bsmw.剑偶.死亡无任务`、`bsmw.毕桃桃.提前死亡` 等失败标记）。与
`BaiShanMiWen.json`（直接补成完成态）不同，本配方**不重玩、不回档**：

* 复活廿一号·剑偶「玉璧」与乌冷霜，玩家可直接进入决战阶段；
* 把白山密闻任务记录还原为进行中（`QC_Started`），并将分支 1「前往正道大营寻找白山派掌门的下落」、分支 2「查看山道尽头毕桃桃的肉身」直接标记完成、分支 3 激活——任务目标即「找到并击败毕桃桃的人偶」（详见下方"游戏引擎 BUG"）；
* 其余任务与收集进度（人偶中枢、幻术琵琶、校场钥匙、各类收集物等）完全不受影响；
* 成就文件不做任何改动（成就只增不减）。

## 游戏引擎 BUG：分支完成判定不触发

完整重放验证（2026.11.05，两次）发现：在这类修复后的存档上，即使任务处于 `QC_Started`、
且阶段事件正常触发（例如接近毕桃桃肉身时 `zddy.毕桃桃.见到肉身` 标记正常置位），
游戏引擎也**不会**把当前分支推进为完成——阶段 1 和阶段 2 会永远卡住。手动把分支
1、2 置为 `BranchCompleted`、分支 3 置为 `BranchActivating` 后，游戏接管正常：

* 任务目标显示为「找到并击败毕桃桃的人偶」；
* 击败人偶「玉璧」后走 `bsmw.剑偶.死亡有任务` 正确路径，游戏自行结算：
  分支 3 完成 → `QC_Succeded` → 两个 NPC spawner 自动写入结局序列
  `Seq081-2-2` → 发放奖励饰品 `AC_HeavyAttackDamage`（残破容器与武器）；
* 乌冷霜会作为流程的一部分重新出场，正常击杀即可。

因此本配方在复活 NPC 的同时直接代为完成分支 1/2，落地即可打最终战。

## 来源与验证

来自玩家真实挽救记录（2026.11.05），经游戏内两次完整重放验证：应用配方后乌冷霜与剑偶
均正常复活，任务直达「找到并击败毕桃桃的人偶」；击败人偶后获得残破容器与武器，游戏
自行结算完成白山密闻（`QC_Succeded`、结局序列、奖励饰品全部由游戏自动写入，与
`BaiShanMiWen.json` 成功态配方的规范值一致）。修改是先对「剑偶死之前」的存档快照
（2Hourly 备份）与失败后的最新存档做全量差异分析，再精确还原白山密闻相关状态得到的。

## 使用方式

```bash
python scripts/complete_quest.py --quest BaiShanMiWen \
    --recipe references/recipes/BaiShanMiWenRevive.json \
    --target <解包目录>/<槽位>.json --out-dir <输出目录>
```

注意必须显式传 `--recipe`，否则会命中 `BaiShanMiWen.json`（补完成态配方）。

## 前置条件（requires 不满足会整体拒绝）

* 首周目（CycleCount == 0）；
* 白山密闻处于 `QC_Failed`，且分支状态为 1:BranchActivating、S1:BranchCompleted；
* 存在失败标记 `bsmw.剑偶.死亡`、`bsmw.剑偶.死亡无任务`、`bsmw.毕桃桃.提前死亡`、
  `zddy.剑偶玉璧.击杀成就计数`；
* 毕桃桃 NPC 处于 `Dead` 姿态、结局序列尚未设置。

## 已知限制

* 清除的 17 个 `ExecuteNodeGuid`「已播放」节点来自该玩家的击杀过程（剑偶死亡演出、
  毕桃桃提前死亡演出、乌冷霜出场/消散，以及若干拾取节点）。其他玩家若流程一致则
  同样命中；若没有对应节点，删除操作按 no-op 处理。副作用最多是路过时重播一段
  一次性对话，不会破坏任何任务的完成状态。
* `QuestGameTimes` 的时间戳会按脚本约定自动改写为目标存档的当前游戏时长。
* 乌冷霜相关标记仅在存在时清除；尚未击杀乌冷霜的玩家跳过这些操作即可。
